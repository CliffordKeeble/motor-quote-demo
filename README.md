# motor-quote-demo

A car insurance quote journey for **Fenmoor Motor**, a fictional insurer. **The insurer does not
exist and the prices are illustrative.** The one real number is Insurance Premium Tax at 12%. It
**stores nothing and logs no answers**: there is no database, and the API's logs hold a quote's
reference and premium and the names of any refused fields, never what anyone typed.

The page asks about the car, the driver and the cover, then shows the price with every step of how
it was worked out, from a starting figure through each answer to the tax.

**Live:** https://wonderful-mushroom-05443000f.6.azurestaticapps.net/ (React; the Angular front end is still to come)

There are two front ends on the same API, React and Angular. They are the same page, screen for
screen, and share their rules for checking answers and their stylesheet (`web/shared`); one
Playwright suite runs the same journey through both.

## The stack, as built

| | |
|---|---|
| Rating engine | C# on .NET 10 (`src/Fenmoor.Rating`): `decimal` money, `DateOnly` dates, no I/O, no clock |
| API | Azure Functions v4, .NET 10, isolated worker with ASP.NET Core integration (`src/Fenmoor.Api`) |
| Front end | React 19.3.1, TypeScript 6.0.3, Vite 8.3.4 (`web/react`), plain React state |
| Front end | Angular 22.2.4, TypeScript 6.0.3 (`web/angular`): standalone components, signals, zoneless, `HttpClient` on fetch |
| Contract | OpenAPI 3.1 (`contracts/openapi.yaml`), TypeScript types generated by openapi-typescript 7.13.0 |
| Tests | xUnit v3 (`xunit.v3` 4.0.2) with `FakeTimeProvider` 10.11.0; Vitest 5.0.5 with Testing Library (React 16.3.3, Angular 19.6.0, user-event 14.6.8, jest-dom 7.0.1) on jsdom 30.1.3; Playwright 1.63.0 through both front ends |
| Typeface | Atkinson Hyperlegible Next 5.3.0, from npm, served from the app's own origin |
| Hosting | Azure Static Web Apps, Free plan (`infra/main.bicep`), one app for each front end; the pipeline deploys the API as each app's managed functions |
| Pipeline | Azure Pipelines (`azure-pipelines.yml`) |

SDK: .NET 10.0.400 or a later 10.0 feature band (`global.json`); built here with 10.0.402. Node 22.
The API and the rating engine target .NET 10 isolated. From 16 to 18 October 2026 they targeted
.NET 9, after a Static Web Apps deploy failure was blamed on .NET 10; it was on Azure's side (the
comment in `Directory.Build.props` says how that was found).
The .NET packages and their versions are in `Directory.Packages.props`: Azure Functions worker
2.52.0, worker SDK 2.1.0, ASP.NET Core integration 2.1.1. npm versions are in
each front end's `package-lock.json`. In `web/react/package.json` an `overrides` entry lets
openapi-typescript 7.13.0 run on TypeScript 6.0: it declares a peer of TypeScript 5.

## How it fits together

```
contracts/openapi.yaml           the contract; the C# and the TypeScript both answer to it
contracts/examples/              the golden example: the worked example's response, exactly
src/Fenmoor.Rating/              the engine
src/Fenmoor.Api/                 GET /api/vehicles and POST /api/quote
web/react/                       the React front end
web/angular/                     the Angular front end, the same page
web/shared/                      what both import: the generated types (api.d.ts), the browser's
                                 checks (validation.ts) and the stylesheet
web/e2e/                         one Playwright suite, run through both
tests/                           xUnit projects for the engine and the API
infra/main.bicep                 the two Static Web Apps
```

The server checks every answer again with the browser's own messages, and a refusal is a 400 with
a message for each failing field. "Today" is the London date. A quote is valid for 30 days.

## Run it locally

You need the .NET SDK, Node 22, and the Azure Functions Core Tools v4 (Visual Studio's Azure
workload brings its own).

Start the API, then the page:

```powershell
dotnet build src/Fenmoor.Api -c Release
cd src/Fenmoor.Api/bin/Release/net10.0
func start
```

```powershell
cd web/react
npm ci
npm run dev
```

Open the address Vite prints. It sends `/api` to the Functions host on `http://localhost:7071`.
The Angular page is the same, from `web/angular` with `npm ci` and `npm start`, at
`http://localhost:4200`, with the same `/api` forwarding.
In Visual Studio, set `Fenmoor.Api` as the startup project and press F5 in place of `func start`
(that route was not exercised when this was written; `func start` was).

## Run the tests

```powershell
dotnet test --solution motor-quote-demo.slnx
cd web/react
npm test
npm run typecheck
npm run contract:check
cd ..\angular
npm ci
npm test
npm run build
```

The Playwright suite runs through both built pages, served with their hosted headers and a stub
of the API that answers only the worked example (`web/e2e/serve-local.mjs`), so it needs no Azure.
Build both pages first (`npm run build` in `web/react` and in `web/angular`), then:

```powershell
cd web/e2e
npm ci
npx playwright install chromium
npx playwright test
```

Set `REACT_URL` and `ANGULAR_URL` to run it against the deployed sites and the real API instead.

## The worked example

Fifteen answers, in `tests/Fenmoor.Rating.Tests/Answers.cs`: a 2021 Volkswagen Golf, a driver born
12 March 1984, a PE postcode, six years of no-claims bonus, comprehensive cover with a £250
voluntary excess and breakdown cover, starting 23 October 2026. It comes to **£227.19 a year**, or
£20.45 a month. "Fill in example answers" on the first page enters the same answers, with a start
date a week ahead so that the form accepts it on any day.

It proves three things. The C# engine produces every line's amount and running total, worked out
apart from the engine. The API's response body for it is byte for byte
`contracts/examples/quote-worked-example.json`. And both pages render that same file line for
line.
